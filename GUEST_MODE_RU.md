# V7: Офер сообщением в Telegram-чате (Guest Mode)

В мае 2026 Telegram добавил **Guest Mode** для ботов. Это отдельный режим, не требующий Business Connection или выбора результатов inline-поиска. Пользователь упоминает бота в чате — Telegram отправляет `guest_message` и одноразовый `guest_query_id`; бот отвечает в том же чате через `answerGuestQuery`, даже если он не участник чата.

## Включение

1. Открой `@BotFather`, его **Mini App** (управление ботами), выбери нужного бота.
2. В настройках включи **Guest Mode**. Это не `/setinline`.
3. После отдельного подтверждения публикации обнови Railway до текущей V7. Переменные остаются прежними; при старте должна примениться миграция `0006_guest_bindings`. В рамках локальной проверки публикация не выполнялась.
4. В личном чате бота введи `/diag`: там должно быть `Guest Mode: ✅ включён`. Если после включения видно ⚠️, сделай Deploy / перезапусти сервис, чтобы `getMe` обновился.

## Отправить тестовое сообщение

Открой обычный личный чат с другим аккаунтом и **отправь** сообщение (без inline-выбора):

```
@your_bot https://t.me/nft/InputKey-25057 1900 15
```

Или для тестовых параметров по умолчанию (изображение также зависит от Telegram):

```
@your_bot #тестофер
```

Замени `@your_bot` на фактический username своего бота. Отправлять команду должен пользователь из whitelist или администратор (создатель офера). Получателю **не требуется** запускать бота или входить в whitelist.

**Ожидаемый результат:** рядом появляется **отдельное сообщение от гостевого бота** (не замена твоей команды) с DEMO-текстом, ссылкой на конкретный NFT, Stars, временем действия и ровно двумя кнопками **«✕ Отклонить»** и **«✓ Принять»**. Telegram самостоятельно решает, покажет ли картинку у данного NFT; при отказе API используется текст без preview. Результат нажатия редактируется в той же гостевой карточке. Реальной продажи, NFT-перевода или списания Stars нет. Если Guest Mode недоступен, включи `/setinline` у BotFather, набери ту же строку и явно выбери inline-результат.

**Ограничения:** Guest Mode поддерживает обычные приватные чаты, группы и супергруппы без контентной защиты; не работает в секретных чатах. Бот заметен как автор отдельного сообщения, исходный текст не удаляется. Точность предпросмотра зависит от Telegram, и вы не можете управлять тем, как конкретный клиент его отрисует. Для любых попыток отправить *из-под аккаунта владельца* без пометки бота нужны другие права, а для безусловной отправки кому угодно разрешений Telegram нет.

## Проверка после установки

1. `/diag` в личном чате бота: Guest Mode включён; Webhook совпадает с Railway.
2. Отправь упоминание с параметрами во втором чате.
3. Проверь появление отдельной карточки (а не просто предпросмотра твоей команды).
4. Нажми **Принять** со второго аккаунта; подпись должна стать **«Принято (DEMO)»** с пояснением об отсутствии сделки. Кнопки решения исчезнут, настроенный контакт поддержки появится, NFT-preview по возможности останется.
5. В другом тестовом чате проверь **Отклонить**.
6. Если карточка не появилась, пришли **только** логи Deploy после отправки команды и ответ `/diag`; не присылай `BOT_TOKEN`, `WEBHOOK_SECRET`, пароли БД.

### Какие файлы меняются в V7

- `app/guest_offers.py` — новый безопасный формат и разбор упоминаний.
- `app/handlers.py` — обработка `guest_message` и кнопок.
- `app/telegram.py` — `answerGuestQuery`, сохранение превью после действий.
- `app/main.py` — определение @username и Guest Mode через `getMe`.
- `app/store.py`, `app/models.py`, `alembic/versions/0006_guest_bindings.py` — привязка гостевого ответа к вызову и защита от повторов.
- `tests/test_v7_guest_mode.py` — локальные тесты.

**Railway Variables не меняются. Миграция `0006_guest_bindings` обязательна; PostgreSQL удалять не нужно.** GitHub и Railway в ходе локальной проверки не обновлялись.
